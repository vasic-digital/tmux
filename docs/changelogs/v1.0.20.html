Revision: 1 Last modified: 2026-05-29T16:30:00Z Version: 1.0.20 / versionCode 21 Released: 2026-05-29 Hosts validated: Mistborn (Darwin arm64) + nezha (ALT Linux 6.12 x86_64)

Summary

v1.0.20 completes the copy/paste story for tmx sessions. Operator-confirmed this cycle: drag-select text, then Cmd-V pastes the selected content. It fixes the prefix P paste binding (which previously produced "a completely new value"), and — the actual reason copy kept failing across earlier "fixes" — it makes config changes reach already-running sessions, so re-opening a long-lived session no longer leaves it stuck on stale bindings.

Together with v1.0.18 (plain-drag select+copy in mouse-tracking apps like Claude Code) and the prefix m mouse toggle, select + copy + paste now work end-to-end with no modifier gymnastics.

Fixed

prefix P paste — POSIX-clean rewrite

The previous binding:

bind P run -b 'tmux load-buffer - <<< "$(#{@clip-read})" \; tmux paste-buffer -p'

was broken three ways:

  1. Nested-quote collision — #{@clip-read} expands to a double-quoted sh -c "…" command; substituting it inside the already double-quoted "$(…)" collided the quotes and mangled the captured text → the operator's "completely new value".
  2. <<< herestring is a bash-ism; run-shell uses /bin/sh, which on Linux is dash → the command fails outright.
  3. \; was passed literally to sh.

Rewritten collision-free and POSIX:

bind P run -b 'sh -c "pbpaste 2>/dev/null || wl-paste -n 2>/dev/null || xclip -o -selection clipboard 2>/dev/null || termux-clipboard-get 2>/dev/null" | tmux load-buffer - && tmux paste-buffer -p'

A single-quoted run-shell wraps a double-quoted inline OS-adaptive probe, piped to tmux load-buffer - then paste-buffer -p (bracketed). No <<<, no format nesting. Verified: real prefix P pastes the EXACT clipboard value, on macOS and Linux.

Stale-running-session config — the true root cause

A tmux server loads its config only at startup. A long-lived session re-opened via the shell-init prompt (tmx attach -t NAME) therefore kept its OLD mouse binding indefinitely — which is why "select/copy" kept failing for the operator even after the config was fixed (a brand-new session worked; the re-opened one did not). Two fixes:

  • tmx attach auto-reloads the shipped config (source-file) into the session before attaching, so re-opening ANY existing session always applies the current bindings. Non-fatal/silent if absent.
  • NEW tmx reload [-t NAME] subcommand source-files the config into running sessions on demand (skips dead socket files via a has-session precheck), without killing the session or losing pane content.
