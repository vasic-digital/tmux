A42 (completed) — plain mouse-drag selects + copies in mouse-tracking apps

Root cause (reproduced with a real mouse). Inside a mouse-tracking app (#{mouse_any_flag}=1 — Claude Code requests alt-screen + ?1003h any-event tracking + ?1006h SGR encoding), tmux's built-in root MouseDrag1Pane forwards the drag to the application (send -M), so a plain drag never reaches tmux copy-mode and selects nothing. The clipboard pipe (@clip→pbcopy/ wl-copy/xclip) and the copy-mode bindings were already correct — the gap was purely that the drag was being handed to the app.

Fix. Override the root drag binding in scripts/tmux.conf.template:

bind -n MouseDrag1Pane if -F '#{pane_in_mode}' 'send -M' 'copy-mode -M'

A plain left-drag now ALWAYS enters copy-mode and begins a selection, even when the foreground app requests mouse tracking. On release, the existing MouseDragEnd1Pane binding pipes the selection to the OS clipboard via @clip. #{pane_in_mode} guard: once already in copy-mode, the drag is passed through (send -M) so copy-mode's own handler extends the selection.

Plain CLICK (MouseDown/Up) and the WHEEL are deliberately NOT rebound, so Claude Code keeps its click + scroll interactivity — only click-DRAG is repurposed for select-and-copy (the Claude Code TUI does not use drag). The fix uses no terminal-specific modifier, so it behaves identically on macOS and Linux. The prefix m toggle and Shift/Alt-drag remain as alternatives.

Captured physical proof (real mouse, no bluff).

  • Cross-platform headless — scripts/tests/56_real_mouse_drag_copy.sh starts a tmux server with the shipped config, runs a mouse-tracking app that enables the exact modes Claude Code uses, attaches a client on a PTY, waits until mouse_any_flag=1, then injects a real SGR-1006 left-button drag (press → motion → motion → release) and asserts the dragged token reached the @clip sink. Asserting mouse_any_flag=1 makes the proof meaningful — at flag=0 even the old forwarding binding would copy. Regression-discriminating: removing the override makes the test FAIL (sink empty). 3/3 deterministic (§11.4.50). Works on macOS AND Linux (no GUI required → runs on headless nezha).
  • macOS GUI layer (opt-in TMX_GUI_TESTS=1) — opens a real iTerm2 window, runs the mouse-tracking app inside a tmux session, performs a genuine cliclick cursor drag across the window, and asserts the token landed in pbpaste. Proven on Mistborn.
  • scripts/tests/55_mouse_toggle_and_copy.sh asserts the override resolves to copy-mode (not the default mouse_any_flag app-forward).
  • Meta-test mutation M-PLAINDRAG strips the override and asserts test 56 FAILs — CAUGHT.
