## Fixed

- **Test 17 (scrollback / copy-mode) load flake — root-caused + fixed, 2 vectors (§11.4.1/§11.4.6/§11.4.50).**
  Flaked under heavy host load (FAIL-bluffs, not a product defect). (1) The T4 generator spelled the
  literal `SCROLLMARK_FIRST`/`SCROLLMARK_LAST` inline, so the terminal's echo of the typed command line
  contained `SCROLLMARK_LAST` and the `GEN_OK` poll matched the command echo before any real output;
  fix assembles the markers from a shell variable (`M=SCROLLMARK; echo ${M}_LAST`) so every grep matches
  REAL OUTPUT only. (2) Under all-core CPU saturation a `capture-pane` grid dump can momentarily lack the
  oldest `FIRST` marker although the buffer genuinely retains all 3000 lines; fix asserts retention via the
  race-free `#{history_size}` counter (`>= 2900`; the no-eviction value is a deterministic ~2982, the OLD
  2000 cap pins it at 2000 and evicts line 1), not a grid dump (T4.3/T4.4 operator copy-mode reach already
  proved retention robustly). Test source only (`scripts/tests/17_scrollback_copy_mode.sh`).
  Determinism (§11.4.50) PROVEN: macOS N=5 GREEN (5/5) + nezha N=20 under full all-core CPU saturation
  GREEN (20/20); `history_size` identical every run (macOS 2981 / nezha 2982 — counter does not race).
- **Tests 12 & 14 (destructive cgroup OOM) — swap-aware OOM (§11.4.81/§11.4.50).** Failed
  deterministically on nezha after the host gained 15 GiB swap (the cgroup enforced MemoryMax
  via swap, `oom_kill`=0). Fix: set `memory.swap.max=0` on the test scope so exceeding the cap
  OOM-kills deterministically (verified `oom_kill` 0 → 295). Now PASS 3/3 each.
- **codegraph macOS skew** (host-level) — stale `~/.local/bin/codegraph` symlink (→ v0.9.9)
  shadowed the npm-managed 1.0.1; repointed → both hosts resolve **1.0.1**.
- **macOS host hygiene** — removed **668 dead tmux test sockets** (678 → 10), no live session touched.
