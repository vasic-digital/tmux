## Fixed — CodeGraph PATH in non-interactive shells (run_all + meta-test)

**Symptom.** The standalone full suite on nezha failed
`20_codegraph_installed.sh` and `22_codegraph_mcp_wired.sh` with "codegraph
CLI not on PATH" / "bare 'codegraph' does not resolve on PATH", even though:
- `@colbymchenry/codegraph@0.9.7` is installed via npm global
  (`~/.npm-global/bin/codegraph`);
- every MCP config (`.mcp.json`, OpenCode, Kimi, Crush, Qwen) is correctly
  wired (those sub-assertions all PASS);
- in an **interactive** login shell (the real agent context) codegraph
  resolves and the tests PASS.

**Root cause.** nezha's `~/.bashrc` begins with the standard interactive-guard
`case $- in *i*) ;; *) return ;; esac` and only adds `~/.npm-global/bin` to
PATH on line 32 — *after* the guard. A non-interactive shell (ssh-batch / CI)
returns before reaching it, so `codegraph` is invisible. `setup.sh` already
worked around this with a top-of-script npm-prefix PATH probe (the A31 nezha
fix, 2026-05-21) — which is why the setup verify gate was green — but the
standalone `run_all.sh` and the meta-test lacked the same probe.

**Fix.** Generalised the A31 probe to `scripts/tests/run_all.sh` and
`scripts/tests/meta_test_false_positive_proof.sh`:

```sh
if ! command -v codegraph >/dev/null 2>&1 && command -v npm >/dev/null 2>&1; then
    NPM_PREFIX="$(npm config get prefix 2>/dev/null | tr -d '\r\n' || true)"
    if [ -n "$NPM_PREFIX" ] && [ -x "${NPM_PREFIX}/bin/codegraph" ]; then
        export PATH="${NPM_PREFIX}/bin:$PATH"
    fi
fi
```

Idempotent (no-op when codegraph is already on PATH, e.g. on macOS via
Homebrew or in interactive shells). After the fix the codegraph tests pass and
the M22 CodeGraph mutation runs **CAUGHT** rather than honest-SKIP on nezha —
the nezha meta-test rose from 46 → 48 mutations caught.
