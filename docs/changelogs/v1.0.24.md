## Summary

v1.0.24 adds an **on-demand container-distribution orchestrator** —
`scripts/tmx-orchestrator/`, a real Go binary that drives the
`vasic-digital/containers` submodule to schedule, deploy, health-check, and tear
down containers on remote test hosts (nezha.local), for heavy testing that
depends on real services running. The tmux product surface (the hardened tmux
3.6a binary + `tmx` wrapper) is **unchanged** from v1.0.23; this release is
testing tooling plus extensions and hardening of the consumed Containers library.

---

## Added

- **`scripts/tmx-orchestrator/`** — Go consumer of the decoupled
  `digital.vasic.containers` submodule (via `replace`, CONST-051). Subcommands:
  - `hosts` — register + SSH-probe configured remote hosts (real `/proc` resources).
  - `distribute` — schedule + `podman run -d -p host:container` a real container on
    the best remote host + poll-until-ready health check (HTTP/TCP).
  - `down` — teardown; **exits non-zero when teardown cannot be confirmed**.
- **`scripts/tests/62_distribution_orchestrator.sh`** — opt-in (`TMX_TEST_REMOTE=1`)
  end-to-end test (build → probe → deploy real nginx + HTTP 200 → teardown). SKIP
  with reason by default; auto-included in `run_all.sh`.
